Fix copy safety before appearance

  1. Honor every destination write failure in the Go engine. mtp/mtp.go:454 ignores the first write result, and :619 shadows the returned error. Use temporary destinations and commit only after success.
  2. Verify known sizes using the full 64-bit value, including zero. MTPCore/Device.swift:171 currently excludes zero and objects at or above 0xFFFFFFFF.
  3. Reject unsupported folder drops visibly until recursive copy exists. OpenMTPApp.swift:188 accepts drops while AppModel.swift:193 skips directory URLs.
  4. Require a deliberate, named confirmation for permanent phone deletion. Bare Delete currently calls deletion immediately at OpenMTPApp.swift:187.
  5. Add explicit queued, active, waiting, failed, canceled and completed job states. Persist only verified checkpoints. An interrupted file must never appear completed.

Native behavior

Use SwiftUI for the shell, sidebar, settings and activity. Bridge AppKit for file promises, mature table editing and Quick Look as needed. Share one device session service per phone, with separate browsing state for each window. The current WindowGroup shares a single AppModel, including selection and navigation.

The current fork supports macOS 13; the Swift package declares macOS 14. Treat that as an explicit compatibility decision. System materials can adapt by OS version without raising the minimum to the latest macOS.

Use system fonts, semantic colors, system toolbar groups and standard content backgrounds. Let system controls adopt the current macOS materials. Keep custom Liquid Glass out of file rows. Check VoiceOver, keyboard-only use, contrast, transparency and motion preferences. Mac guidance · Materials · Accessibility

Adopt familiar file commands: Return to rename, Command-O to open, Command-Up for the enclosing folder, Shift-Command-N for a new folder, Space for Quick Look and Command-Delete for the deliberate delete command. Put actions in File, Edit, View and Go menus and resolve them against the focused pane. Offer a legacy shortcut preset for your existing muscle memory. Apple shortcut reference

Use file promises for Finder drag-out, so a drop chooses the destination before downloading. Add Quick Look through a managed local cache; some formats require the full file. File promises · Quick Look

One job engine, capability-aware connections

USB MTP, no phone appOne active MTP operation per device. Batch metadata, cache folder handles, stream with bounded buffers, and use optional partial-object operations only when supported.Keep command ordering and USB short-packet rules intact.
Network transfer with a cooperating peerA phone service or an existing compatible server must provide remote listing, reads and writes. Then use authenticated streaming, range resume, checksums and optional delta transfer.A QUIC or TCP connection alone cannot provide Android file access.

One operation at a time is an MTP constraint, not a reason to block the interface. USB request queueing and disk work can overlap inside a data phase. MTP 1.1 specification, section 4.3.1 · libusb asynchronous I/O

  1. Batch directory metadata and reuse handles. Invalidate affected caches on copy, rename, delete, device events and reconnect. Fall back when the phone's implementation is incomplete.
  2. Overlap USB or network I/O with disk reads, writes and hashing. Use a small reusable buffer pool and backpressure. Preserve one MTP operation at a time; asynchronous USB requests can still feed its data phase.
  3. Benchmark larger request sizes and bounded request depths. Choose the smallest settings that reach a throughput plateau without harming memory use, interaction latency or cancellation.
  4. Keep Smart Sync's metadata fast path, but describe it honestly. Equal size and timestamps are not proof of equal content. Add optional verification and preserve case-sensitive names and conflicts.
  5. Add durable range checkpoints for supported downloads. Upload resume needs verified remote partial-write support. Revalidate device identity, object identity, size and modification state after reconnect.
  6. For cooperating network peers, transfer only changed blocks when saved network time exceeds scanning, hashing and patching cost. Whole-file streaming remains the useful default for new videos and already compressed media. Apply compression selectively.

Initial tuning experiments can compare 64 KiB, 256 KiB, 1 MiB and 4 MiB requests with depths of one, two and four. Prefer the smallest setting within 5% of the best repeatable result, with a 16 MiB per-device buffer budget. These are starting hypotheses. Retain a conservative device fallback and preserve ordering, response boundaries and buffer lifetimes.

For interactive browsing, schedule metadata between files. When partial reads work reliably, test 8–32 MiB ranges and allow browsing requests between them. Use weighted round-robin scheduling with aging so small files do not starve large videos. USB buffer size, scheduling range and durable resume checkpoint size serve different purposes.

Resume needs a journal of source identity, expected size, committed ranges and available content hashes. MTP handles can change after reconnect, so resolve and validate the source again. Android edit and partial-object commands exist, but support must be tested on each phone. AOSP MTP server

For network peers, compare TCP with TLS and QUIC under the same conditions. Use transport flow control and congestion control, persistent streams and bounded concurrency. Size the application window against measured bandwidth and RTT within a memory cap; do not acknowledge each application chunk in a stop-and-wait loop. QUIC does not automatically combine USB, Wi-Fi and Ethernet. QUIC · QUIC recovery and congestion control

Evaluate rsync-style rolling checksums for similar existing files and FastCDC for content-defined deduplication across repeated datasets. Use a modern strong digest for verification. The remote peer must compute or retain trusted block information; reading the whole destination through MTP just to hash it may cost more than copying. Bluetooth likewise requires a supported peer service and should favor reduced bytes and selective compression. Rsync algorithm · FastCDC paper

Expose connection capabilities above the USB-specific protocol. A shared file-service API should distinguish listing, streaming, range reads, partial writes, rename, events and remote checksums. That prevents unsupported Pause or Resume actions from reaching the UI.

How to establish a speed improvement

Measure directory-open latency, time to first byte, sustained useful bytes per second, total completion time including commit, CPU, peak memory, retries and UI response. Compare the fork and native app on the same phone, direction, cable, port and data. Sweep request size and depth; test tiny files, mixed trees and files larger than 4 GiB. For network peers, include LAN and high-latency or lossy links. Exercise unplug, disk-full, device-lock and cancellation recovery separately from speed tests.

The current mtpctl bench-pull discards received bytes. Use it to isolate USB and protocol performance, then measure full copies including filesystem writes, synchronization and optional checksum verification. Keep these results separate.

The earlier small-buffer versus large-buffer comparison is a simulator submission-count experiment. It is neither a hardware throughput result nor an execution of the Go implementation. Larger host requests do not change the USB packet size.
